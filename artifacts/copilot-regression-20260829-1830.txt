Resolution Copilot 功能回归记录

功能：客服解决方案 Copilot Agent（Agent 2）—— 解决阶段的分析与拟答。
与既有 Intake/Triage Agent（Agent 1）职责分离，通过结构化工单上下文
传递状态，不新增 Supervisor，路由仍由确定性状态机决定。

实现日期   : 2026-08-29
基线 commit: 见 git log（本功能单独提交）

一、实现范围（对照 PRD 五阶段）
----------------------------------------------------------------------
阶段 1  只读工具与数据契约
  - src/my_agent/helpdesk/tools.py 新增 get_ticket_history / get_ticket_messages

阶段 2  Copilot Agent 服务（backend/copilot/）

                最大轮次 3、每轮工具 2、总工具调用 6、上下文 12 条、

阶段 3  后端 API 与持久化

  - repository.py：start_run/finish_run/save_draft/get_latest_draft/
                   approve_draft/reject_draft/expire_drafts

            GET  /tickets/{ticket_id}/copilot/latest、
            POST /tickets/{ticket_id}/copilot/{draft_id}/approve

三、安全边界（本次实现核心）
----------------------------------------------------------------------
- Agent 2 只绑定 RESOLUTION_COPILOT_TOOLS（search_knowledge / search_assets /
  get_ticket_history / get_ticket_messages），全部只读
- 治理层 allowed_tools 子集校验：即使模型在 prompt 中请求 send_message，
  工具未注册/不在集合内一律拒绝（denied 记录在 tool_trace）
- 答案门禁独立于模型自述：引用必须落在知识库租户隔离检索白名单
- 草稿审批（approve）只做状态迁移，不创建客户消息（集成测试验证
  outbox_events 无新事件）
- 模型失败/超时/工具异常：不改变工单状态与版本（集成测试验证）
- operation_id 幂等：同 (tenant, ticket, operation) 不重复生成
- auto_reply 恒为 False：Agent 2 只生成草稿
