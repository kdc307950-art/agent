# V1 产品范围说明（一页）

> 目标发布日期：2026-09-12（计划） · 实际执行日：2026-09-03（命令输出 date +%F） · 版本标识 `2026-09-12-v1` 仅指目标范围
> 一句话：**面向中小企业内部 IT 服务台：员工从 Web 报障碍，系统自动完成分类、补字段、SLA、派单与带引用建议，人工确认后解决关闭；企业微信等渠道保留代码但为“非 V1 能力”。**

## 目标客户

- 中小型企业（百人级）内部 IT 支持团队；租户 = 一家企业，租户内隔离。
- 使用人：员工（提交障碍）、IT 客服（接单/处理/回访/关闭）、IT 管理员（策略与知识维护）。

## V1 只做三类工单

| 类别 | 示例 | 知识依据（seed_demo） |
| --- | --- | --- |
| `it.vpn` | 连不上、报错 809/769、频繁掉线、远程办公 | vpn-001 |
| `it.account`（账号/权限） | SSO 登录失败、忘记密码、账号锁定、申请权限 | password-001 / permission-001 |
| `it.network` | 办公区断网、Wi-Fi 连不上、DNS/IP、网关、延迟 | network-001 |

其他 IT 子类（email/hardware/software/printer）保留既有能力，但不作为 V1 主演示链路，也不在演示脚本中承诺。

## 主链路（唯一验收路径）

```text
Web 建单（V1 唯一渠道）→ 受理图分类（it.vpn / it.account / it.network）
  → 必填字段追问（客户按“字段:值”补充） → 命中所属 IT 策略 → 加载 SLA
  → 派单 team-it → 知识检索生成带引用建议（无证据不自动发送）
  → 客服接单/处理 → 发起回访 → 客户确认 → 关闭 → 全程审计
```

## 非目标（V1 明确不做）

- 财务 / 行政 / 产品等业务类工单：命中后统一转服务台人工队列，不做自动处置。
- 通用聊天、天气、计算器等 legacy 能力：保留代码，标记 legacy-demo，非产品入口。
- 更多渠道（电话、邮件、IM 机器人等）：V1 仅 Web；企业微信/钉钉代码保留为非 V1 能力，不在演示与验收中承诺。
- 复杂多 Agent 编排 / 行业扩展。
- 未评测的 LLM 自动分类：V1 分类以确定性关键词分类器为基线，LLM 仅作为建议/草稿生成。

## 人工介入规则（谁必须兜底）

出现以下任一情况 → 转人工（不自动回复、不自动发消息）：

1. 分类命中非 IT 大类（finance/admin/product/other）或无法识别；
2. 分类低置信度 / 多类并列；
3. 必填字段多次追问后仍缺失（追问耗尽）；
4. 敏感操作 / 高影响 / 高风险（删除数据、权限开通、全公司、生产环境…）；
5. 无知识依据或无引用（有证据才建议：自动草稿引用支撑率须 100%）；
6. 身份上下文缺失（无 tenant_id / 无 user_id）→ 收紧权限并人工接管。

## 验收指标（V1 门槛）

| 指标 | 门槛 |
| --- | --- |
| 分类 Top1（三类场景单列） | ≥ 90% |
| 字段补全成功率 | ≥ 95% |
| 自动草稿引用支撑率 | 100% |
| ACL 越权 | 0 |
| 端到端成功率 | ≥ 90% |
| P95 | 记录当前机器基线，后续版本劣化 ≤ 20% |
| 成本 | 接入真实模型单价后才有量化值，V1 报告为 N/A |

## 与面试口径一致性

- 说“中小企业内部 IT 服务台”；说“VPN、账号/权限、网络故障三类”；
- 说“AI 只做有证据的建议、人负责确认与兜底”；
- 不说“通用客服/财务报销/多行业智能体”。
